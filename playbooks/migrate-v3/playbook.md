# Adopt a legacy backlog into the store

For projects created before taskmaster 6.0, whose backlog lives in `.claude/` or the project root. `backlog_migrate_v3` (alias `backlog_migrate_v4`) moves it under `.taskmaster/`, opens the SQLite store, and projects the backlog back in the current layout. The name is historical; there is no v2 to v3 file rewrite any more. Go through this playbook rather than calling the tool cold, because adoption rewrites every projection file and the user should see what moves before it moves.

1. Call `backlog_store_status`; it is read-only, so it neither adopts nor errors on a legacy layout the way `backlog_status` would before the user has answered. `no backlog found at`: hand off to `taskmaster:init-taskmaster`. `Error: backlog lives at <dir>` (a `.claude/` or root backlog) or a `Warning:` that says `no store yet` (a `.taskmaster/backlog.yaml` from before the store): continue. A `Store:` report without that warning: already adopted, so say so; re-running is harmless and only re-reports counts. On a native store (`schema v2`) no migration applies.
2. Tell the user what adoption does, then ask Adopt or Cancel<!-- cc-only:start --> (one `AskUserQuestion` with those two options)<!-- cc-only:end -->. Heavy fields land in `.taskmaster/tasks/<id>.md`, the derived `context:` block leaves `backlog.yaml`, id-less epics, phases and tasks get deterministic ids, and `viewer.json`, `auto/`, `snapshots/` and `PROGRESS.md` move under `local/`. Files are moved, never deleted. On a few thousand files it takes minutes. Cancel stops here.
3. Call `backlog_migrate_v3()` and show the response as it is. Success starts `Adopted into the store (backlog_migrate_v3).` and gives the store path, schema version, max seq and row counts. `Error: ...` (no backlog, several `backlog.yaml`, a canonical layout that already holds different content, or unsafe storage) means nothing moved; stop and report it. `adoption refused: ...` means a rendered file did not read back as written. It names the entity, nothing on disk changed, and the empty database was removed. Fix that entity, then re-run once; retrying without a fix gives the same refusal.
4. If a viewer tab is open, ask the user to hard-refresh it.

Per-field moves and edge cases: `references/migration-steps.md`.
