# N08 evidence: existing clients routed through the native core

Branch `feat/native-n08-routing`, based on `9d17431` (the N07 merge). Nothing was
pushed, merged, activated or run against a live project; the installed plugin and
every project's `.taskmaster/` are untouched. The CodeMaestro evidence below was
taken on scratchpad copies of an existing scratchpad copy, never on the live project.

N08 does not address the CodeMaestro performance failure. That is a separate
investigation; nothing here measures or claims a speed-up.

## How routing works

Every MCP tool is registered through `_GuardedToolRegistrar`, which now wraps it in
`_route_native` (commit `e5f241a`). On each outermost call the wrapper asks
`native_routing/gate.py` whether the project's store is a ready native authority:
`meta.schema_version = '2'`, a `native_manifest` with `authority=native`,
`state=ready` and `local_state_imported=1`, a matching store identity, and a
SQLite build that passes the JSON/FTS5 probe. The check opens the database
read-only and reads no projection file.

- **Legacy store (every real project today):** the answer is `NotImplemented` and
  the tool body runs exactly as before. The full suite is the evidence that this
  path did not move.
- **Native store:** `registry.dispatch` binds the call's arguments with their
  defaults and hands them to the family adapter. The adapter reads through
  `Repository` snapshots, writes through `commands.execute`, and runs the
  synchronous compatibility drain before it returns.
- **Native store, unrouted tool:** the call is refused with an `Error:` sentence
  and nothing changes. There is no fallback writer to route to: the legacy
  `Store` refuses a schema-2 database (`UnsupportedStoreError`), and any write to
  the legacy tables would fire the invalidation trigger and mark the manifest
  stale.

Only tests make a store native (`tests/native_twins.py::activate_native`). No
startup path, operator command or runtime entry point writes the markers.

### The synchronous compatibility drain

`native_routing/projection.py` preserves today's file visibility. After each
native command it claims the pending `projection_jobs` inside `BEGIN IMMEDIATE`,
coalesces them per file and renders with the same renderers the legacy store uses.
Commit `b6637bd` moved those renderers into shared functions
(`store.render_entity_file`, `render_backlog_file`, `detect_dominant_crlf`). The
drain also keeps `backlog.yaml` and `ideas/IDEAS.md` current by comparing
`MAX(last_seq)` against `projection.exported_seq`. The derived backlog fields
(`bugs`, `issues`, `trackers`, `handovers`, `threads`, `thread_meta`) are
recomputed from live rows at read and export time (`derived.py`), with keys sorted
the same way the legacy JSON sorts them.

### Proof method: twins

`tests/native_twins.py` seeds a legacy project through the public tools, copies it
byte for byte and activates the copy. Each call runs on both projects, and three
things are compared:

1. **The answer text.** `[seq N]` is normalized and each project's root is spelled
   `<root>`.
2. **Committed entity state,** field by field, timestamps included.
3. **Every projected file.**

Both runs of one call read a shared fake clock, so second-boundary flakes cannot
hide or invent a difference. The viewer twins compare HTTP status, JSON body and
ETag presence.

### Hooks

The three store-reading hooks gained a native branch. The shared helpers live in
`native_routing/hook_reads.py`, which imports only the standard library,
`taskmaster.admission` and `taskmaster.native`; a check with `yaml` and `fastmcp`
blocked confirms nothing heavier loads.

- **Edit resurfacing** matches paths through `entity_paths JOIN entity_core`. It
  takes the revision from `MAX(domain_events.seq)` instead of the frozen `changes`
  table.
- **The merge gate** reads the policy from the native project row and the task
  from `task_operational.branch_json` plus a `Snapshot`.
- **The merge recorder** finds the task the same way. It takes the merge ladder
  from the project row, not from `project.yaml`, then stamps through the routed
  `backlog_record_merge`.

Before this change, an activated store would have silenced resurfacing, **opened
the merge gate** (its store read failed, and a gate that cannot read fails open),
and let the recorder look branches up in the frozen legacy `entities` table.

## The five constraints

1. **Completion changelog: refuse, route nothing twice.** The plan's two options
   both proved infeasible (see "Where the plan was wrong"). On a native store,
   `backlog_complete_task` with `session_title`, `done` or `auto_summary` answers
   `CHANGELOG_REFUSAL` and changes nothing. A completion without a changelog is
   routed normally. No paragraph is queued in either store, so nothing can render
   twice when N11 lands, and nothing is lost silently: the caller is told to log
   the summary separately. Tested in `test_native_routing_tasks.py`. The paragraph
   has to be queued once N11's drain exports it.
2. **Batch partial apply.** The adapter pre-validates every line against an
   overlay of the snapshot, using the legacy line rules, which are now pure
   functions in `native/batch_lines.py`. It then submits the accepted lines as one
   native batch of `task.batch_line`/`epic.batch_line` operations and reports
   per-line errors exactly as the tool does. `tests/test_batch_partial_apply.py`
   is parametrized over legacy and native and passes on both. A mutation that
   forwards the raw line-set fails it.
3. **Presentation belongs to the adapter.** The core returns receipts. Rendered
   answers come from pure presentation helpers extracted from the legacy tool
   bodies (`_bug_list_text`, `_handover_get_text`, `_status_text`,
   `_task_full_from`, …). Legacy tools and adapters both call these helpers, so
   there is one copy of every string.
4. **`task.pick` takes an explicit `session`.** The adapter passes the server's
   `SESSION_ID` as `session` for single and bundle picks. Session identity never
   enters the database.
5. **Activation stays gated.** No startup cutover, no activation command, no
   change on legacy stores. The routing wrapper answers `NotImplemented` for every
   non-native store before any native import.

## The bypass gate

`tests/test_native_bypass_gate.py` enforces the gate in four ways.

**Dynamic rig.** On a native twin it replaces these legacy entry points with
functions that raise `BypassViolation` (a `BaseException`, so no adapter
`except Exception` can swallow it): `_load`, `_load_snapshot`, `_store`,
`_store_for`, `_transaction`, `_store_tx`, `store.load_dict`,
`transaction_dict`, `transaction`, `open_store`, and the matching `Store`
methods. It also guards reads, globs, listdirs and walks under `.taskmaster/`.
The exceptions are `local/`, `linear.yaml`, `taskmaster.json` and calls made from
inside the export drain. Under the rig the gate runs:

- all 91 routed tool/action exercises (answers starting `Error` fail the
  exercise);
- the 27 viewer routes over real HTTP;
- the three hooks.

Separate tests prove the rig catches a legacy load, a projection listdir, a
projection read and a legacy tool body.

**Static scan.** An AST scan of every `native_routing` module rejects the legacy
names. The only allowlisted names are the export drain's line-ending sample and
the store-status listing of `local/`.

**Ledger.** `UNROUTED_NORMAL_PATH` is the exact set of normal-path
(targeted-query, simple-command, composite-command) inventory pairs with no route.

**Normal-path fallback count: 0.** Every normal-path tool and action in
`tests/fixtures/native_contracts.json` is routed.

`backlog_validate` is routed as well (`da0308c`, `4037446`). It is inventoried as
maintenance, but it is the integrity check operators actually reach for. On a native
store it reads trackers and artifact tldrs from rows rather than files, so it
reports no file-level YAML damage: a native store never reads its exports back.

Eleven inventory pairs remain unrouted, all allowlisted maintenance or
synchronization operations. On a native store each one refuses, changes nothing, and
says why and what to do instead. The text comes from `registry.GUIDANCE`. A test
(`tests/test_native_routing_refusals.py`) holds that table equal to the unrouted
inventory, so a newly unrouted tool cannot fall back to a bare refusal. Each answer
begins `` `tool` cannot run here: this project's store is a native authority``, ends
`Nothing was changed.`, and uses the tool's own error shape (JSON for
`backlog_link` and `backlog_linear`). In between, the operator sees:

| Tool / action | Category | What the operator is told (after the common opening) | Owner |
|---|---|---|---|
| `backlog_init` | maintenance | the project is already initialized; use `backlog_status` to see it | none needed |
| `backlog_migrate_v3`, `backlog_migrate_v4` | maintenance | the store is past every legacy migration; adopting it into the legacy store would undo that, and the legacy store refuses native databases; no migration is needed; use `backlog_store_status` | N15 (cutover tooling) |
| `backlog_canonicalize_layout` | maintenance | a native store can only live under `.taskmaster/`, so the layout is already canonical; no action is needed | none needed |
| `backlog_backfill_lanes` | maintenance | the one-time lane backfill has only a legacy implementation; set a lane per task with `backlog_update_task(task_id, field="lane", value=...)` and use `backlog_skip_gate` for gates in-flight work already passed | N15 |
| `backlog_index_status` | maintenance | there is no separate derived index to report or rebuild, because search and graph tables are maintained inside every command; use `backlog_store_status` | N15 |
| `backlog_link` reconcile | maintenance | every link write records its inverse in the same transaction; run `backlog_link(action="validate")` and fix findings with create or remove | none needed |
| `backlog_handover_resync` | synchronization | handovers are rows, edited handover files are never read back, and the next write to a handover re-exports its file over hand edits; the index and cap are maintained on every write; use `backlog_handover_update_status` or `backlog_handover_supersede` | N11 to N13 (file import) |
| `backlog_issue_resync` | synchronization | issues are rows and the issue index is derived on every read, so there is nothing to resync, and edited issue files are never read back; use `backlog_issue_update` | N11 to N13 |
| `backlog_linear` bootstrap_apply | synchronization | adding a workspace still writes `linear.yaml` under the legacy store's config lock; add it to `.taskmaster/linear.yaml` by hand with ids from `backlog_linear(action="probe")`, and `backlog_validate` checks the file | N13 |
| `backlog_linear` retry | synchronization | pushing queued changes needs native synchronization, which has not shipped; queued changes are kept and `backlog_linear(action="status")` lists them | N11 to N13 |

A tool added later without an entry gets a generic native-authority refusal, and the
guidance test fails until it gets one. The maintenance scripts under `scripts/`
(`_store_rows.py`, `backfill_tldr.py`, `migrate_links.py`,
`migrate_handover_statuses.py`, the benchmarks) are explicit maintenance, are not
routed, and none runs on a normal path.

## Intentional differences from the legacy tools

1. **Archiving stamps `archived`.** A status change to `archived` (update, batch
   line or viewer archive) records `archived: <now>` natively; legacy flips only
   the row flag. Placement and every other field match.
2. **A completion carrying a changelog is refused** (constraint 1).
3. **More than 100 accepted batch lines are refused whole** (`MAX_BATCH_COMMANDS`)
   rather than applied in one unbounded transaction.
4. **Non-text area anchors are refused.** Legacy stored `[1, 2]`.
5. **Store status is compared by its labels.** Its figures describe different
   physical tables.
6. **Native reads never run the one-shot legacy handover-status backfill.** A
   cutover (N15) must perform it once.
7. **Native completions do not regenerate the PROGRESS.md dashboard** (N11).
8. **The resurfacing hook's revision is a domain event sequence,** so a session's
   `hook-seen` memo written before activation can re-show one line once.
9. **`backlog_validate` checks rows, not files.** It cannot report a tracker or
   artifact file that fails to parse, because a native store never reads its
   exports back; everything it checks from committed data matches legacy.
10. **The eleven refusing operations answer with operator guidance** in place of
    what they did on a legacy store.

## Legacy defects found and pinned, not fixed

- `backlog_link` between two non-task entities answers success but its transaction
  is never latched, so the link is rolled back. The native core commits it. This is
  pinned as a recorded difference.
- `GET /api/dashboard/recent-events` compares naive and aware datetimes and drops
  the connection when tool-created tasks exist. The native route fails identically;
  the parity test pins both.
- `test_bundle_pick.py` leaks the process-global session bundle into later tests
  (see Validation). The N08 harness now resets it; the leaking test is unchanged.
- On Windows, `backlog_store_status` on a freshly copied project can raise
  `SystemError` from `os.kill(pid, 0)` in `_local_pid_alive`. Seen while preparing
  the CodeMaestro copy; not routed-path behaviour.

N07-era core defects found by the twins and fixed:

- `thread.update` read the backlog under the id `backlog`.
- `decision.update` had no operation.
- Link removal's `any()` removed only the first type.
- Handover membership and auto-link had gaps.
- Links synthesized from legacy fields were missing.
- A bundle pick touched every member.
- Phase advance broke order ties differently.
- Supersede refused a missing target that legacy tolerates.

## Where the plan was wrong

- **Neither changelog option works.** "Keep completion on the legacy writer until
  N11" is impossible: the legacy writer cannot open a native database. "Pass the
  paragraph only to the legacy queue" fails too, because that queue is a `meta`
  write, and any legacy-table write invalidates the native manifest. Refusal is the
  only option that neither loses nor duplicates text.
- **"Track remaining fallback calls" presumed a fallback.** No native-to-legacy
  fallback can exist; the only remaining choices are "routed" and "refused".
- **Field order is not preserved by a structured store.** Answers rendered in dict
  order needed the snapshot to sort top-level fields as legacy JSON does.
- **Backfill entity order mattered.** Keys were allocated in id order, so list
  answers diverged from legacy insertion order until `c15f77d`.
- **Hooks were listed as files but not as risks.** An activated store would have
  opened the merge gate silently.

  - the revision stays frozen (revision test fails);

  concurrency test:**
  `test_native_bypass_gate.py::test_routed_tool_never_reaches_the_legacy_store_or_scans_the_projection[backlog_thread_update.None]`,
