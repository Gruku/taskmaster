## Decision F1

The user chose option A on 2026-09-23. Public `related`, `links`, `handover_tasks` and
`entity_paths` stay **current at commit**, maintained incrementally, with the full oracle
as an explicit repair operation. On-demand materialization is recorded as a later

[N02 spec](../specs/2026-09-09-native-compatibility.md).

## What changed

- **Indexed incremental path neighbourhood** (`native/neighbourhood.py`). A path edit used
  to compare against every anchor/location row. It now uses indexed exact lookups, a
  downward literal-prefix walk for reverse globs, and literal-prefix ranges for own
  globs. Candidates are partitioned by rowid, and `fnmatchcase` still makes the final
  decision.
  - New native-only partial and expression indexes on `entity_paths`, plus
    `handover_tasks(task_id)` and `entity_core(public_id, deleted, kind)`. They are built at
    backfill and, for stores activated before N14, on the first admitted command. No
    schema version change.
- **Canonical neighbourhood read** `Snapshot.neighbourhood`. The native edit hook counts
  neighbours through it and no longer reads `related`. The hook revision is the event
  high water plus `graph_repairs`.
- **`backlog_dependencies`.** Native downstream reads, and the viewer dependency half, use
  the `dependencies` target index; the viewer no longer loads the task tree. There is a new
  additive strict `depth` (1–10, default 1 = unchanged output), traversed level by level on
  both stores. Limits: 200 tasks per direction, a 5 s deadline, cycles and unreadable
  entries reported.
- **Native graph verify/repair** through `backlog_index_status(verify=True | rebuild=True)`.
  The core is `native/graph_repair.py`, run as the `graph.repair` command. It runs once at
  activation (`migrate.repair_graph_for_activation`, inside the authority-switch
  transaction), and never during a repeatable backfill.
- **Link fixes on both stores.** Links written before their target existed are
  re-resolved when the target is created. An id that is both an epic and a phase now
  resolves the same way on both stores. The kind lookup is indexed (`ix_entities_id` on
  legacy, where it is transparent).

## Reviews

Every step had an independent adversarial review, and every finding was fixed test-first.

- **Steps 1–4:** round 1 found 7 issues:
  - a non-string handover id left the neighbourhood one-sided;
  - prose rows were not counted as work;
  - the bound computation was O(L²) for long anchors;
  - plus test gaps.

  Round 2 found 3: NUL paths were double-counted, the lazy index creation was placed badly,
  and the native hook tests bypassed real ingress.
- **Step 5:** round 1 found 6, including a CTE blow-up with timeouts, a target scan, and the
  viewer loading the whole tree. Round 2 found 2 plus nits: a quadratic readability check,
  and O(shown × edges) rendering outside the deadline.
- **Step 6:** round 1 found 5; the main one was `links` not current at commit for links
  written before their target. Round 2 found 3 more:
  - the epic/phase tie-break differed between stores;
  - backfill repaired graph tables that legacy still owned;
  - the kind lookup was a full scan.
