# N13 implementation evidence (in progress)

This milestone is **not accepted**. Development is isolated in `feat/native-n13`
at `.worktrees/native-n13`, based on N12 checkpoint `eee4799`. N12's full suite
runs on its frozen worktree; no N13 tests have run alongside it. N12 fixture

## Import preparation: initial focused evidence

- Shared pure authored-file parser used by the legacy Store and native import
  preparation. It preserves unknown fields and task prose, validates identity,
  and enforces epic/phase slim-versus-document ownership.
- Known-path discovery, canonical-first duplicate reporting, link/reparse-point
  refusal, bounded byte reads and before/after file identity checks. It does not
  claim to sandbox a hostile process continuously replacing ancestor directories.
- Exact observed/published bytes retained atomically with their projection hash;
  no freshly rendered document is substituted as a three-way base.
- Per-field merge with absence distinct from null and booleans distinct from
  numbers. Current claims and push receipts remain local; terminal/archive
  imports cannot revive stale holders.
- Read-side candidate preparation and bounded native `sync.apply`: database
  revision/manifest fencing; event/history, graph/search and export intent in one
  transaction; quarantine/conflict bytes retained; missing-file repair separate
  from domain deletion; reserved/tombstoned IDs never resurrected.

Independent review of the first slice found backlog input could restore an
absent heavy field owned by its entity document, and a tracker import could
overwrite its durable Linear UUID while keeping its push receipt. Both were
corrected and given regression cases. The command review then found imported
numeric IDs did not advance their allocator counters, and reflag/resolution
could discard an older exporter-captured external version. Both writer-side
fixes were included in the first focused run: **99 passed, 1 skipped in 49.47
seconds** (`n13-import-first.out.log`). The skip required symlink creation
permission. This run also covered an injected failure after multiple entity
writes and asserted complete rollback of entities, counters/reservations,
events/receipts, bases, search and export jobs.

## Subsequent barrier work (verified; see review fixes below)

After that run, explicit sync IPC, durable begin/completion records, completion
status lookup and a publication -> writer-execution pause were added. Service
protocol is now 2, so a stale N12 owner refuses the new client rather than
partially accepting synchronization. Candidate bytes are checked before
submission, after commit and after publication. The captured sequence is finite;
later queued commands cannot interleave with that publication. Active sync keeps
the coordinator from expiring as idle.

Path safety is now shared by import, native publication and the renderer's
line-ending probes. Tests for barrier races, completed/lost-response replay,
linked paths and shared publication guards are written but have not run. The
barrier is undergoing independent static review. This is not managed-Git or
linked-worktree acceptance.

## Barrier review fixes

An independent static review of the coordinator barrier found six defects.
Locking order, replay, stale-file rechecks and protocol-2 refusal were clean.

1. HIGH: an `UnsafePath` from the path guard escaped the CRLF probe, the
   batch render and publication. One linked entry, or a missing `.taskmaster`
   root, stopped every export. It also returned an error for a committed
   legacy `execute`. Fixed (a253ffd): refused or missing paths cast no CRLF
   vote. A refusal now affects only its own job, which returns to pending
   with an `export pending: <rel> refused (...)` notice. The drain still
   never raises. The guard now refuses symlinks and name-surrogate reparse
   tags (bit 0x20000000: symlink, junction), plus reparse points whose tag
   cannot be read. Cloud and dedup placeholders still publish.
2. MEDIUM: the writer pause relied on an unfair RLock race. Fixed (48e60bd):
   there is now an explicit admission gate. After dequeuing, the writer waits
   outside `execution` while a sync pause is held. The sync therefore waits
   for at most the one command already in flight. A writer-busy timeout
   releases the pause. The continuous-writes test also passed before the fix
   on this machine (the starvation did not reproduce with Python 3.12 on
   Windows), so the gate is verified directly by a deterministic test.
3. MEDIUM: the pause test was strengthened. It polls for 0.5 s while pinned
   and reads the published file at a new `sync_published` checkpoint.
4. MEDIUM: added tests for the recheck after publication, stub exporters
   that return pending or raise, uncertain begin/import/finish, and
   publication beside a real junction (`_winapi.CreateJunction`).
5. LOW: a `flush_through` beyond MAX(seq) is now refused before `sync.begin`
   and before any import. After imports, it is reported as pending (56ab36e).
6. LOW: `sync.finish` now stores a bounded summary: a receipt key per import,
   capped warnings, `*_omitted` counts and a 256 KiB budget. The caller
   receives exactly the stored value. Finish has its own minimum timeout, and
   any finish failure is reported as pending (56ab36e).

Focused evidence: 341 passed and 3 skipped (symlink-privilege skips) across
`tests/test_native_sync_*.py`, `test_projection_parse.py`,
`test_native_service*.py`, `test_native_projection*.py`, `test_store_bypass.py`
and `test_store_root.py` with `-n 6`. The full suite was not run here.

## Step 7 routes

Branch `feat/native-n13-routes` (from `06a6251`). N11's deferred refusals are
lifted; the native guidance table loses three entries.

- **`backlog_resolve_conflict take="file"`** (`68f590a`) calls
  `client.sync(files=[file], take_file=True)`: parse checks identity, the
  manifest token (flag, trusted base, publication) and entity revisions fence
  `sync.apply`, and the bytes are rechecked before submit and after commit. Only
  entities the file names are replaced. Absent rows are never deleted. Unknown
  fields and the observed bytes survive, the bytes in the `sync.apply` event.
  A take that does not parse, or names a tombstone, now refuses instead of
  quarantining. Wrong identity, a store write after parse and a file edit after
  parse all refuse, and the file bytes and flag stay untouched.
- **Handover/issue resync** (`83314cb`, `7c0018b`) import every path of that kind
  through the same barrier. The paths are the canonical files discovered on disk
  plus every path the store records. On a store-recorded path conflict the
  recorded path wins; the second copy is reported. Edits merge on a trusted base
  and are flagged-and-kept without one. A missing file is repaired, never
  deleted. An unparseable file is quarantined with its bytes kept and imported
  once repaired. Discovery runs in the MCP process. The bypass rig now sanctions
  `coordinator/sync_files.py` as the import reader.
- **Linear `bootstrap_apply`** (`48eff6e`) is a new coordinator method,
  `linear_bootstrap`. Under `publication` (10 s, then "publisher busy"), it
  parses `linear.yaml`, appends and validates. Then
  `native.projection.replace_config` writes a synced temp, rechecks the parsed
  bytes and renames; it uses no-overwrite when creating the file. Other
  workspaces and unknown keys survive. `token_env` must be an env-var name;
  `lin_api_`/`lin_oauth_` values refuse. Any failure leaves the file and no temp.
  An identical retry answers `unchanged` (a deliberate difference from legacy,
  for lost responses). Argument parsing is shared with legacy
  (`_linear_workspace_entry`).
- **Barrier review item:** the pending sync result returned to the caller is
  bounded to 256 KiB, in this order: unresolved, notices, imports, warnings.
  What is dropped is counted in `*_omitted`.

Focused evidence (`-n 2`): 287 passed (bootstrap, refusals, bypass gate,
legacy Linear tools/config/writer, service Linear, contracts, workflow), and
263 passed, 2 skipped (symlink privilege) across the take-file, resync, sync
prepare/commands/files/merge/base, service/sync/adapter, projection resolve,
progress, conflict flag, handover body and store bypass files. The full suite
was not run.

### Step 7 review fixes

An independent review of the five route commits found six defects. Everything
else it checked was clean: claims, receipts, Linear-id protection, fences,
missing-file repair, the read-only `sync_files`, bootstrap atomicity and
old-owner refusal. Each fix below has a failing regression test first.

- **HIGH: backlog.yaml imported task rows** (`ec2a2ad`). `flatten_backlog` keeps
  legacy inline `epics[].tasks` entries, and `sync_prepare` passed them through.
  `take="file"` then replaced the whole task row with the stub: 14 fields became
  `{epic,id,title}`, and the stub was re-exported. Ordinary sync created any new
  task an inline stub named. Now `take="file"` refuses such a file ("tasks are
  owned by their task documents"), and nothing changes. Ordinary sync
  quarantines it with the same reason. `sync.validate` rejects `task` rows from a
  `backlog` import. `flatten_backlog` is unchanged because legacy adoption still
  needs inline tasks. The multi-row rollback test now uses two epic rows.
- **MEDIUM: bounded result could hide the named import** (`61d8c5d`).
  `bound(result, named)` keeps the entries for files the caller named before
  anything else. Beyond that it still keeps unresolved, then notices, imports and
  warnings. When a receipt is omitted, `_take_file` reports "outcome unknown;
  inspect receipt_scope". It never says "nothing changed" in that case.
- **LOW: lost reply followed by a same-id retry** (`61d8c5d`). The retry sees the
  file as `unchanged`. Before refusing, `_take_file` now checks whether the flag
  is gone and the recorded hash equals the file on disk. If both hold, it
  reports the file as resolved.
- **LOW: Linear credential outside `token_env`** (`94f4032`). `team_id`, `alias`
  and both sides of every mapping now refuse the `lin_api_`/`lin_oauth_`
  prefixes.
- **LOW: a second store-recorded path was dropped silently** (`8ef1139`). It now
  gets the same "second copy ... skipped" warning as a duplicate on disk.
- **Housekeeping** (`8ef1139`). `test_native_workflow` now maps both resync tools
  onto `sync.begin/apply/finish` instead of listing them as deferred to N13.

Focused evidence (`-n 6`): 372 passed and 2 skipped (symlink privilege) across
these files: take-file, resync, linear bootstrap, sync base/commands/files/
merge/prepare, service sync, projection parse, workflow, routing refusals,
bypass gate, and linear config and writer. The full suite was not run.

## Suite health

- **Shutdown race** (`3b04786`). The writer-wait notice pump is a daemon
  thread. It used to `print` through `sys.stderr`, which holds the stderr
  BufferedWriter lock for the whole write syscall. If a process exited while the
  pump was mid-write, CPython aborted: `_enter_buffered_busy ... at interpreter
  shutdown`, exit 0xC0000409. That is how the stress test's worker failed. The
  pump now writes the raw stderr fd with `os.write`, which takes no Python lock.
  The reporting call is unchanged and still non-blocking. The regression test
  floods notices into a stderr pipe that nobody reads, then exits. It failed
  before the fix and passed 3/3 after. The other daemon threads (viewer and
  coordinator HTTP servers, session heartbeat, coordinator writer/exporter)
  do not write to stdout/stderr on their normal paths.

- **Load-only barrier flakes** (`a7e5a6e`, `92a7d48`). Two tests failed in a
  loaded `-n 4` full run and passed alone. Both hit the same cause: the
  background exporter held `publication`. The first was a product gap. A
  `timeout=0` flush that lost the race to the exporter's once-a-second PROGRESS
  retry answered only `publisher busy`, which hid the PROGRESS debt a later
  barrier must name. The busy reply now checks `owes_through` too, and the test
  holds `publication` to exercise that path. The second was test timing. The
  startup export pass stalled behind the blocked writer's write transaction,
  so sync stopped at `publisher busy` before it sent begin. The test now waits
  for that pass first. Holding the lock, or adding a 0.4 s drain delay,
  reproduced both failures. After the fixes, each test passes 10 plain and 10 slowed runs.
- **Grouping** (`3a02425`). A scratch plugin counted the Python children each
  test starts across the 28 files that spawn processes: 173 tests, 475 passed,
  310 s at `-n 2`. Six tests run more than one child at the same time. At most 8
  at once: stress test and `test_simultaneous_fresh_process_opens...`. At
  most 4: `test_concurrent_process_start_elects...`. At most 2:
  `test_two_processes_compat...`, `test_two_process_writers...` and
  `test_two_processes_exporting...`. These six share
  `xdist_group("heavy_processes")`. `tests/conftest.py` switches xdist's
  default `load` to `loadgroup` and passes that choice to the workers. Without
  xdist it does nothing. The next-longest tests
  (4-15 s: kill matrices, merge hooks) run one child at a time and are left
  ungrouped.
- **Why the stress test takes 8-9.5 min.** Contention and lock hand-off are not
  the cause. 8 processes x 50 ops ran 535 calls in 82 s. One process doing
  536 calls with no contention took 100 s. The cost per write grows with the
  size of the store. With one worker, a call took 123 ms in the first quarter
  of the run and 244 ms in the last quarter (236 entity files).
  - `_scan_projection`: 9→53 ms per write. Every write stats every projection
    file.
  - `_projection_schema`: 3→12 ms, parsed 4x per tool call. **Fixed**
    (`1f0b9c3`): the result is cached by the file's inode, mtime_ns and size.
    Measured afterwards: last quarter 244→172 ms per call, total tool time
    100→83 s.
  - Constant per-write costs: `_export_touched` ~23 ms and two
    `_try_register_session` commits ~12 ms each. The test's own `store.status`
    call after every tool call adds ~13 ms.

  At 8x200 (~2,100 calls, ~1,000 entities) this O(N)-per-write scan explains
  the ~500 s. The full-scan-per-write design is a design question and is left
  open. The "63.0s of 30.0s" line is not a deadline overrun. It is a synthetic
  notice from `test_the_writer_wait_sink_never_blocks_its_caller`
  (`update_root_config`, waited=index, deadline 30). Its 64 queued lines drain
  into the xdist worker's stderr once its fake sink unblocks. The stress
  workers never call `update_root_config`.
- **Overload reply raced a reset.** `test_transport_capacity_refuses_without_starting_another_owner`
  failed once under load: the client launched a startup contender against a
  live owner. The owner's over-capacity path sent its 503 without reading the
  request and then closed the socket. On Windows, closing with unread bytes
  sends RST, so the client could get `ConnectionAbortedError` instead of the
  503. The client treated any reset, timeout or garbled reply as a dead owner
  and launched. The owner now reads the request (bounded by
  `MAX_MESSAGE_BYTES`), replies, half-closes and waits for the client to close,
  all within 0.5 s on the accept thread. The client now launches only on a
  missing discovery record or a refused connection. After any other transport
  error it checks the kernel ownership lock. If the lock is held, it raises a
  retryable `ServiceUnavailable` that keeps the request_id. If the lock is free,
  the record is stale (its port may now belong to another process) and it
  launches as before. New tests: a 1 MB request to a full owner gets the
  structured 503 10/10 times (it failed with `ConnectionAbortedError` before
  the fix); a resetting listener behind a live owner's record raises without
  launching; the same listener behind a stale record still launches.

## Step 8 managed Git

Branch `feat/native-n13-git` (from `b958100`): plan `c63de42`, containment
`fc33165`, managed operation `d7d3535`, CLI/hook `d97222a`, test fix `5dd6dbb`.
No hook was installed anywhere real; all Git work ran in temp repositories.

Implemented:
- `coordinator/job.py` (ctypes, no new dependency): private job
  `Local\taskmaster-git-<128-bit>` with an owner-only protected DACL. It refuses an
  existing name and sets kill-on-close and die-on-unhandled-exception with no
  breakaway flag.
  `contained.py` + `git_helper.py`: a hidden helper blocked on an owned stdin
  pipe, assigned (membership verified) before permission. EOF before permission
  never launches Git. An unassigned helper exits; an assigned one holds its
  inherited job handle until it is retired.
- `coordinator/git.py`: `git_run` (commit/checkout) holds `publication` across the
  whole sequence. It refuses when a lock, pin, marker or non-top-level root exists.
  It runs the step 6 barrier with import (`synchronized` required) and checks
  that the disk matches the published generation. The durable `git.managed` marker
  (`synchronous=FULL`) is written before the job exists, and phase `launch` is
  written before permission. Commit = `git add -A --pathspec-from-file` (projection
  files plus tracked deletions), then `git commit`. Checkout adds a post-import
  sync inside the same hold. After retirement to an active count of 0, the outcome
  is classified from HEAD/ref/index/locks. A commit tree's `.taskmaster` blobs are
  verified against the published bytes. Completed/failed clears the marker and
  writes `git.last` (so a same-request retry replays and never re-runs Git).
  Ambiguous stays pinned.
- The pin gates the exporter, `flush`, `sync` and Linear bootstrap. Startup pins
  before the exporter runs; a recovery thread retires the recorded job, then
  reconciles. `git_recover(acknowledge_quiescent, accept_outcome)` exists for
  states that cannot be proven. SERVICE_PROTOCOL is now 3.
- `git_cli.py` (commit/checkout/status/recover). `git_hook.py pre-commit` is for
  users to call from their own hooks. It admits only a token-matched managed
  generation whose staged blobs equal the published bytes. It refuses unmanaged or
  stale projection staging with guidance.

Verified (`-n 2`, git tests in `heavy_processes`):
- The job, managed, crash and hook files passed 3 of 3 repeated runs after the
  teardown-lag test fix (24 then 13 tests per run).
- Focused regression: **305 passed, 2 skipped** in 199 s across the git files,
  service/sync/process/ownership/adapter/linear/progress/routing, linear
  bootstrap, bypass gate, take-file, resync and process-liveness. The full suite
  was not run.
- Crash windows: the test-owned coordinator subprocess is killed through its own
  Popen at pre-assignment, pre-permission, active Git (a pre-commit hook paused in
  the temp repo) and completed/pre-receipt. At the replacement's
  `git_recovery_retiring` checkpoint the pin is set and the racing domain write is
  unpublished. `flush` answers pending, and the job still has members (>= 3 while
  Git is active). At `git_recovery_quiesced` the active count is 0. Outcomes:
  pre-assignment, pre-permission and active Git are `failed`, with HEAD unchanged
  and no hook run without permission. Completed/pre-receipt is `completed` with
  exactly +1 commit and a verified generation. Only then does the write publish.
- Other tests: a writer racing staging (the store commit stays out of the commit
  and is published afterwards), a whole multi-file generation, Git failure, nothing
  to commit, refusals, the pin on every path, a checkout with post-import, a
  missing job after `launch` pinned until acknowledged, `prepared` + missing job
  proven not launched, ambiguous pinned across restarts until accepted, and a
  non-Windows marker surviving two ordinary restarts.

Not done / limits:
- There is no POSIX boundary. An interrupted operation stays pinned until the
  operator acknowledges it (checked by a platform-marker test; not run on POSIX).
- Kill-on-close fires only when the helper dies too: the helper deliberately
  holds the job so recovery can prove it. An orphaned helper waits idle until the
  next coordinator starts.
- A `launch` marker whose job is missing (helper killed externally, reboot or a
  different session namespace) needs operator acknowledgement. Reboot is not
  detected.
- An older coordinator binary started directly ignores the marker.
- A stale `index.lock` left by a retired commit is reported, not removed.
- Linked worktrees (step 9) are refused as non-top-level. Bypassed-checkout drift
  detection (step 10) and the copy-only rehearsal are not done.

### Step 8 review fixes

Two independent reviews reproduced the high findings with scratch probes. Each
fix below was test-first (the regression failed before the fix):
- H1/L1 (`6cf8efd`): a venv `python.exe` is a launcher. The process assigned to
  the job was the launcher, and the real helper and Git ran outside it. The
  helper now starts as the base interpreter with `-I -S`, so no site or `.pth`
  code runs before assignment. It also verifies its own membership before running
  anything. M6(a), L2 and L5 are in the same commit: the inherited handle is
  query-only, recovery opens with query|terminate, and an unassigned helper never
  holds when membership cannot be proven.
- H2 (`15c9e02`): a managed checkout no longer imports. Paths whose bytes differ
  from the published generation are recorded in `git.drift`: older files, files
  missing on the target, and files only the checkout has. They are held from
  export and skipped by ordinary sync, so nothing is applied or repaired. Drift
  resolves when the published bytes return, through `take_file`, or through
  `git recover --release-drift`. Managed Git refuses while drift exists. Step 9
  adds per-checkout bases.
- H3 (`92e37b4`): a checkout that leaves `index.lock` behind, or changes the
  index or the worktree fingerprint, is `ambiguous`. The fingerprint is taken
  after the barrier. A crash test pauses a real checkout in a smudge filter.
- M1-M5, L6 (`eeac56a`): `prepared` settles as not launched and ignores later
  commits. A commit is verified against the blob ids recorded at capture, and
  requires its `Taskmaster-Op` trailer. `commit --only` leaves user-staged
  work staged. Per-request receipts cover up to 32 requests, and the marker's own
  request never re-runs. `acknowledge_quiescent` together with `accept_outcome`
  settles as `accepted` (unreconciled). M6(b) is recorded in the scope doc.
- L3/L4/L7/L8/L9/L10 (`85f2477`): the marker records the logon session and
  integrity level. Managed Git runs with gc, maintenance and fsmonitor disabled.
  `quiesced` is durable before reconcile. An uncontained (POSIX) helper exit
  only previews the outcome until someone acknowledges it. `generation.through`
  is the barrier's target. New tests cover the real uncontained path, the
  exporter under a startup pin and the Linear bootstrap refusal. The crash
  windows now assert non-publication unconditionally.
