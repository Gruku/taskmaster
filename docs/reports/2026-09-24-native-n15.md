# N15 report: migration and downgrade rehearsal

Status: **complete locally; native activation remains a release decision.** No live project
was migrated. Scope: [`2026-09-24-n15-scope.md`](../plans/2026-09-24-n15-scope.md). Runbook:
[`native-cutover.md`](../runbooks/native-cutover.md). Branch `feat/native-n15`.

## Decisions

- **M1 = A (user, 2026-09-24):** no reverse migration to the old format. Rollback is exact
  before activation; after activation the only way is forward. The escape hatch is to flush
  the projection files and re-adopt them into a fresh legacy store. Authored documents
  survive; DB-local state (receipts, sessions, history seq) does not.
- **Simplified rollback (user, 2026-09-24).** Four review rounds kept finding defects in
  automatic file/row restore and discard, so rollback now restores **nothing**. It clears the
  fence and native staging only when the store is healthy and its rows, ID sidecar and
  projection files still match the latest backup. Anything else refuses and names every
  difference, offering three choices:
  1. `--resume`: go native and keep the writes;
  2. `--rollback --clear-orphan-fence`: stay legacy and keep everything;
  3. the runbook's manual restore, which discards the writes after copying aside what it
     replaces.
- **Drift-absorption cap:** at most 3 absorptions per invocation, recorded in the journal. A
  cap per cutover trapped writes once reached; this change follows the rule that no path may
  trap an acknowledged write.

## What was built

- **`taskmaster/native/cutover.py`** and its CLI, `python -m taskmaster.native.cutover --root …
  [--dry-run|--resume|--rollback] [--confirm-stopped] [--clear-orphan-fence] [--token] [--json]`.
  - **Journal** in its own table (`native_cutover_journal`). Writing to `meta` would invalidate
    the verified staging.
  - **Stages:** fence (`meta.migration_state=migrating`, with owner and token, under the
    coordinator ownership lock and `BEGIN IMMEDIATE`; admission lets only the token holder
    through), reconcile (flushes pending exports itself), backup (a consistent SQLite copy plus
    a projection-file archive, carry-over snapshot and digest, all under one write lock),
    backfill, compare (a rolled-back trial activation), activate, release.
  - **Activate** is one transaction: schema and protocol markers, authority, graph repair, ID
    import, progress reconcile, `verify_carryover` (if it finds anything, everything rolls
    back), and carried dirty rows queued as native export jobs.
  - **Drift absorption:** a write that leaks through the fence is detected and absorbed by
    re-running reconcile → backup → backfill under the fence.
  - **Integrity check** at start and inside activation. A damaged store is refused and pointed
    at the manual restore, or at the escape hatch once activation has committed.
  - **Exit codes:** 0 done, 1 fence up, 2 refused, 3 failed before any fence.
  - **`tests/native_twins.py`** flips authority through the production `activate()`. With
    `TASKMASTER_TWINS_VERIFY=1`, the default in `tests/conftest.py`, every twin activation also
    runs the carry-over oracle (+2.3 % time).
- **`taskmaster/native/carryover.py`:** the carry-over oracle (`snapshot_carryover` /
  `verify_carryover`) over the retained tables, the Linear queue, projection and quarantine
  flags, sessions, `meta`, ID high water and reservations, tombstones, history seq and both
  pending changelogs. Also `import_id_state`, moved from test scaffolding into production, and
  `reconcile_progress`, the explicit form of N11's seed.
- **`taskmaster/native/quiesce.py`:** best-effort detection, stdlib only.
  - `live_owner` finds a live coordinator.
  - `open_writers` catches any open connection under WAL.
  - `scan_processes` matches the launcher inventory through CIM on Windows and `/proc` or `ps` on
    POSIX; `--confirm-stopped` gets past it.
  - Pre-bridge binaries can only be detected, not refused, so the runbook's stop list is the
    control.
- **`docs/runbooks/native-cutover.md`:** the stop list, commands and expected output, recovery
  per stage, the escape hatch, a manual restore that can be executed and is guarded (a test
  runs it literally), and backup pruning.

## Reviews

Every round was an independent adversarial review, and every finding was fixed test-first
(regression tests confirmed failing on the previous code).

- **Track B (oracle and quiesce):** built against a fixed interface and integrated in track A.
- **Round 1:** rollback silently restored over a write acknowledged after the backup (HIGH).
  Also: a manifest that was never synced stranded resume; uncaught errors misreported the fence;
  the dry run changed store bytes; the handover-status latch was skipped; and more (9 findings).
- **Round 2:** resume could never absorb a leak (HIGH); rollback's diff, save and restore ran
  unlocked, so a racing write was lost (HIGH); discard left projection files diverged; and more
  (10 findings).
- **Round 3:** a resume/rollback deadlock on dirty projections (HIGH); stale native staging
  blocked a re-cutover (HIGH); index-only damage triggered a blind restore (HIGH); a
  snapshot/backup race; and more (7 findings plus 3 suspicions).
- **Round 4:** resume undo reverted an acknowledged write (CRITICAL), and the reviewer judged
  the design not converged. The user chose to simplify.
- **Round 5 (simplified design):** converged, with no path that loses a write. Resume activated
  a damaged store (HIGH); a missing backup or archive wedged both commands; the refusal text was
  wrong; the restore script had no guards; and more (8 findings).
- **Round 6:** fit to merge after one fix: the pruning one-liner deleted the newest same-second
  backup.

## Validation

Full suite on `54f9be4`: **4,343 passed / 1 failed / 4 skipped**, 1,935 s, `-n 3`, run on its
own. The single failure was the architecture guard `test_the_native_core_never_imports_a_remote_client`,
because `cutover.py` imported `socket` for the host name. It was fixed with `platform.node()`
(the same value) in `19da0de`. The guard and all 140 cutover and crash tests pass after the fix.
An earlier run at `-n 2` was stopped by Claude Code under memory pressure while the rehearsal ran
alongside it. Heavy runs must run alone.
