# N07 evidence: complete lifecycle and composite commands

Branch `feat/native-n07-lifecycle`, based on `feat/database-native-foundation`
at `9bf22a8`. Nothing was pushed, merged, activated or run against a live
project; the installed plugin and every project's `.taskmaster/` are untouched.

## One rules layer, not two

`taskmaster/native/domain.py` (commit `ce2e1b9`) now holds the task/epic/phase
rules that previously existed only inside `backlog_server`: the status-transition
table and `illegal_transition_message`, the completion gate rule, gate record/
skip/clear and merge-ladder transforms, archive reasons and the archivable/
pickable/completable state sets, priority normalization, field allowlists, epic
component validation, phase deliverable commands and the date/slug predicates.
They are pure functions with no database, filesystem or implicit clock: every
timestamp arrives as an explicit `now` argument.

`backlog_server` imports them rather than redefining them, so the MCP tools, the
viewer HTTP write path and the native core apply the same rule objects — a new
regression test asserts the names are absent from `backlog_server`'s own module
body and that the objects are identical. The N02 contract inventory script reads
those constants from the shared module, and `tests/fixtures/native_contracts.json`
is byte-for-byte unchanged, so the frozen compatibility contract did not move.

## What was ported

`taskmaster/native/workflow.py` (commit `562708c`) adds 26 operations to the
single command owner, bringing the accepted native operation set to 44:

| Family | Operations |
|---|---|
| Task lifecycle | `task.create`, `task.update`, `task.pick`, `task.complete`, `task.archive` |
| Gates and ladder | `task.gate`, `task.gate_skip`, `task.gate_clear`, `task.merge`, `task.spec_review`, `task.spec_review_clear` |
| Epic and phase | `epic.create`, `epic.update`, `epic.archive`, `phase.create`, `phase.update`, `phase.advance` |
| Promotion and links | `bug.promote`, `link.create`, `link.remove` |
| Settings | `area.create`, `area.update`, `thread.update`, `project.set` |
| Linear | `linear.link`, `linear.unlink` |

Each is one `BEGIN IMMEDIATE` transaction owned by `commands.execute`, reusing
the existing receipt, event, revision and selective-maintenance machinery. The
composites carry their side effects inside that same transaction:

- **Completion** refuses while an open bug names the task through `found_in`
  (matched case-insensitively, as the legacy close-gate does), applies the
  lane's outstanding-gate rule, archives the bugs the task fixed, and closes or
  flags the open handovers the task belonged to. All of it rolls back together.
- **Archive** applies the same handover smart-close and emits both the
  old-file delete and the new-file write projection intents.
- **Epic archive** cascades to every live task under the epic in one commit and
  refuses a second archive.
- **Phase advance** blocks on unchecked deliverables unless forced, marks the
  active phase done, archives that phase's done tasks and activates the next
  planned phase by order.
- **Bug promotion** creates the issue and flips every source bug to `promoted`
  atomically; one missing bug leaves no issue behind.
- **Typed links** write the inverse on the target, refuse invalid type/kind
  domains, refuse `depends_on`/`blocks` cycles, and are idempotent.
- **Auto-link** scans `notes`/`review_instructions` plus the body for inline
  mentions, adds `references` links for targets this database holds, writes each
  `referenced_by` inverse, and skips unknown targets — all without a file read.

`commands.py` gained caller-derived id allocation for the named kinds (task,
epic, phase, area, tracker, project). Ids are reserved in `id_reservations` and
never recycled, including after a row is removed. Projection paths now cover
epics, phases, areas, trackers and `project.yaml`; the backlog document has no
per-entity file and so emits no job.

## What the invariants cost

- **No remote call, and no config read, inside a transaction.** `linear.link`
  writes the tracker row and the task's `tracker_id`; task mutations enqueue one
  `task_upsert` on the retained `linear_queue` table. The trigger is a tracker
  row the database already holds, so nothing reads `linear.yaml` inside the
  writer. A test asserts no native module imports `httpx`, `requests`, `urllib`,
  `http`, `socket` or `taskmaster.integrations`.
- **Queue maintenance rebuilds no unrelated graph.** A metadata edit on a synced
  task reports zero global graph rebuilds, zero path comparisons and zero
  link-pair work in its receipt, and a rolled-back composite leaves no queued
  push.
- **Handover smart-close costs one list query.** The planner only carries each
  handover's body through untouched, so bodies are fetched only for the
  handovers it actually changes rather than for the whole directory.
- **The changelog paragraph moved tables.** It commits with the transition that
  produced it, but into native `sync_state` under `pending_progress_log`, not the
  legacy `meta` row: every `meta` write fires the staging-invalidation trigger by
  design, so a native command cannot use it. Rendering the paragraph stays with
  the adapter. **The N11 exporter must drain this key**; until it does, the
  legacy `meta` row remains the legacy exporter's own source and the two are not
  yet reconciled.

## Intentional differences from the legacy tools

These are behaviour changes, recorded rather than hidden:

1. **Batches are all-or-nothing.** `backlog_batch_update` applies the lines it
   can and reports per-line errors; the native `batch` is the N05 structured
   batch and rolls back entirely on the first refusal. The N08 adapter has to
   pre-validate lines if it wants to keep the tool's partial-apply reporting.
2. **`task.pick` takes an explicit `session`.** Session identity, the "current
   task" pointer and the session bundle are caller state, not database state.
   Lock eligibility, the foreign-lock refusal and `force` are native; atomic
   claim/renew/expiry is N09.
3. **The Linear enqueue gate is a tracker row, not `linear.yaml`.** Legacy also
   required the config file on disk. The native gate is strictly database-derived
   so no file is read inside the writer.
4. **Presentation is not ported.** Rendered strings, the epic `max_tasks` budget
   warning, worktree instructions and the next-task suggestion belong to the N08
   adapter; the native commands return receipts.
5. **`link.create`'s `note` is accepted and not stored**, exactly as the tool
   behaved — the argument was only ever echoed.
6. **Typed links still resolve kinds by id prefix.** `entity_kind_of` recognizes
   `T-`, `ISS-`, `IDEA-`, `HND-` and date-slug ids only, so a kebab-prefixed task
   id is refused as an invalid source. This is the existing tool behaviour,
   mirrored deliberately rather than quietly fixed; changing it is a compatibility
   decision, not an N07 port.
7. **Task id high-water seeding.** The fixed-prefix kinds keep the "high-water
   was not imported; refusing allocation" refusal. Epic-prefixed task ids have no
   counter to import for a newly created epic, so the allocator seeds the
   high-water from the live rows *and* the tombstone reservations under that
   prefix. It never recycles an id.

## Validation

Python 3.12.9 / SQLite 3.47.1 in the isolated worktree venv.

- `tests/test_native_workflow.py`: 41 cases, all passing. They cover id
  allocation and non-recycling, unresolved-reference rollback, lane and gate
  derivation, exclusive claims and forced transfer, bundle picks, gate ordering
  and `gate_state`, skip audit trails, merge ladder state, spec-review plus its
  legacy mirror, the bug close-gate, fixed-bug archiving, handover smart-close,
  the changelog queue, archive projection moves, the transition table, epic
  cascade, phase exclusivity and advance, bug promotion, link inverses and cycle
  refusal, auto-link, area/thread/project settings, the Linear outbox, batch
  atomicity and the inventory-coverage check.
- `tests/test_native_domain_rules.py`: 19 cases asserting the rules exist once.
- Native suites together (`workflow`, `lifecycle`, `commands`, `contracts`):
  75 passed.
- Full suite, single process: **2,569 passed, 1 skipped, in 1,174.90 seconds**
  (`python -m pytest tests/ -q`), zero failures and zero errors. The skip is
  `test_smoke_full_push_round_trip`, which needs live Linear. The pre-change
  baseline measured on this branch after the rules extraction was 2,509 passed /
  1 skipped in 827.00 seconds (8 processes); the 60 additional cases are exactly
  the 41 workflow cases plus the 19 rules cases. The run covers the committed
  tree; the only later change was moving two imports to the top of
  `tests/test_native_workflow.py`, after which that file's 41 cases were re-run
  and passed.
- `tests/test_native_contracts.py` passes unchanged, so the frozen N02
  compatibility fixture did not drift.

No benchmark was run for N07; the N16 acceptance matrix still owns performance.

## Where this does not reach

Native activation stays gated. No `Store` startup path invokes this core, there
is no operator activation command, and only tests set the native authority
markers. The legacy tools still write through the legacy path: N08 is what routes
them here, and until it does, "the existing completion/gate/claim, handover,
batch, auto-link and Linear test suites pass" means those suites still pass
unchanged *and* the same contracts are now separately proven against the native
core — not that their calls travel through it.
