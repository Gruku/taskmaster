# N07 evidence: complete lifecycle and composite commands

Branch `feat/native-n07-lifecycle`, based on `feat/database-native-foundation`
at `9bf22a8`. Nothing was pushed, merged, activated or run against a live
project; the installed plugin and every project's `.taskmaster/` are untouched.

## One rules layer, not two

`taskmaster/native/domain.py` (commit `ce2e1b9`) now holds the task/epic/phase
rules that previously existed only inside `backlog_server`: the status-transition
table and `illegal_transition_message`, the completion gate rule, gate record/
skip/clear and merge-ladder transforms, archive reasons and the archivable/
pickable/completable state sets, priority normalization, field allowlists, epic
component validation, phase deliverable commands and the date/slug predicates.
They are pure functions with no database, filesystem or implicit clock: every
timestamp arrives as an explicit `now` argument.

`backlog_server` imports them rather than redefining them, so the MCP tools, the
viewer HTTP write path and the native core apply the same rule objects — a new
regression test asserts the names are absent from `backlog_server`'s own module
body and that the objects are identical. The N02 contract inventory script reads
those constants from the shared module, and `tests/fixtures/native_contracts.json`
is byte-for-byte unchanged, so the frozen compatibility contract did not move.

## What was ported

`taskmaster/native/workflow.py` (commit `562708c`) adds 26 operations to the
single command owner, bringing the accepted native operation set to 44:

| Family | Operations |
|---|---|
| Task lifecycle | `task.create`, `task.update`, `task.pick`, `task.complete`, `task.archive` |
| Gates and ladder | `task.gate`, `task.gate_skip`, `task.gate_clear`, `task.merge`, `task.spec_review`, `task.spec_review_clear` |
| Epic and phase | `epic.create`, `epic.update`, `epic.archive`, `phase.create`, `phase.update`, `phase.advance` |
| Promotion and links | `bug.promote`, `link.create`, `link.remove` |
| Settings | `area.create`, `area.update`, `thread.update`, `project.set` |
| Linear | `linear.link`, `linear.unlink` |

Each is one `BEGIN IMMEDIATE` transaction owned by `commands.execute`, reusing
the existing receipt, event, revision and selective-maintenance machinery. The
composites carry their side effects inside that same transaction:

- **Completion** refuses while an open bug names the task through `found_in`
  (matched case-insensitively, as the legacy close-gate does), applies the
  lane's outstanding-gate rule, archives the bugs the task fixed, and closes or
  flags the open handovers the task belonged to. All of it rolls back together.
- **Archive** applies the same handover smart-close and emits both the
  old-file delete and the new-file write projection intents.
- **Epic archive** cascades to every live task under the epic in one commit and
  refuses a second archive.
- **Phase advance** blocks on unchecked deliverables unless forced, marks the
  active phase done, archives that phase's done tasks and activates the next
  planned phase by order.
- **Bug promotion** creates the issue and flips every source bug to `promoted`
  atomically; one missing bug leaves no issue behind.
- **Typed links** write the inverse on the target, refuse invalid type/kind
  domains, refuse `depends_on`/`blocks` cycles, and are idempotent.
- **Auto-link** scans `notes`/`review_instructions` plus the body for inline
  mentions, adds `references` links for targets this database holds, writes each
  `referenced_by` inverse, and skips unknown targets — all without a file read.

`commands.py` gained caller-derived id allocation for the named kinds (task,
epic, phase, area, tracker, project). Ids are reserved in `id_reservations` and
never recycled, including after a row is removed. Projection paths now cover
epics, phases, areas, trackers and `project.yaml`; the backlog document has no
per-entity file and so emits no job.

## What the invariants cost

- **No remote call, and no config read, inside a transaction.** `linear.link`
  writes the tracker row and the task's `tracker_id`; task mutations enqueue one
  `task_upsert` on the retained `linear_queue` table. The trigger is a tracker
  row the database already holds, so nothing reads `linear.yaml` inside the
  writer. A test asserts no native module imports `httpx`, `requests`, `urllib`,
  `http`, `socket` or `taskmaster.integrations`.
- **Queue maintenance rebuilds no unrelated graph.** A metadata edit on a synced
  task reports zero global graph rebuilds, zero path comparisons and zero
  link-pair work in its receipt, and a rolled-back composite leaves no queued
  push.
- **Handover smart-close costs one list query.** The planner only carries each
  handover's body through untouched, so bodies are fetched only for the
  handovers it actually changes rather than for the whole directory.
- **The changelog paragraph moved tables.** It commits with the transition that
  produced it, but into native `sync_state` under `pending_progress_log`, not the
  legacy `meta` row: every `meta` write fires the staging-invalidation trigger by
  design, so a native command cannot use it. Rendering the paragraph stays with
  the adapter. **The N11 exporter must drain this key**; until it does, the
  legacy `meta` row remains the legacy exporter's own source and the two are not
  yet reconciled.

## Intentional differences from the legacy tools

These are behaviour changes, recorded rather than hidden:

1. **Batches are all-or-nothing.** `backlog_batch_update` applies the lines it
   can and reports per-line errors; the native `batch` is the N05 structured
   batch and rolls back entirely on the first refusal. The N08 adapter has to
   pre-validate lines if it wants to keep the tool's partial-apply reporting.
2. **`task.pick` takes an explicit `session`.** Session identity, the "current
   task" pointer and the session bundle are caller state, not database state.
   Lock eligibility, the foreign-lock refusal and `force` are native; atomic
   claim/renew/expiry is N09.
3. **The Linear enqueue gate is a tracker row, not `linear.yaml`.** Legacy also
   required the config file on disk. The native gate is strictly database-derived
   so no file is read inside the writer.
4. **Presentation is not ported.** Rendered strings, the epic `max_tasks` budget
   warning, worktree instructions and the next-task suggestion belong to the N08
   adapter; the native commands return receipts.
5. **`link.create`'s `note` is accepted and not stored**, exactly as the tool
   behaved — the argument was only ever echoed.
6. **Typed links still resolve kinds by id prefix.** `entity_kind_of` recognizes
   `T-`, `ISS-`, `IDEA-`, `HND-` and date-slug ids only, so a kebab-prefixed task
   id is refused as an invalid source. This is the existing tool behaviour,
   mirrored deliberately rather than quietly fixed; changing it is a compatibility
   decision, not an N07 port.
7. **A bundle pick can still re-open a `done` member.** Excluding archived
   members restores the tool's own filter, but `_find_tasks_by_bundle` also
   counts `done` members, so picking any member flips a finished one back to
   `in-progress`. That is the legacy behaviour and it is preserved here rather
   than corrected under an N07 port.
8. **Handover smart-close is no longer best-effort.** The tool wraps the
   planner in `try/except Exception: return []`, so a handover it cannot
   evaluate leaves the task transition alone. The native composite has no such
   guard: a planner failure rolls back the whole completion or archive. That is
   deliberate under a transactional core — a completion that half-applied its
   handover side effect is worse than one that refuses — but it is a real
   behaviour change, not a port.
9. **Commands are not replayable to a byte-identical document.** The runtime
   purity trap found the clock to be the only reachable impurity, and it is
   reached ambiently rather than passed in: `domain.now_stamp`/`today_stamp`,
   the event timestamp, the receipt clock, the changelog entry and seven
   `taskmaster_v3` document builders reached through `lifecycle.apply` and
   `bug.promote`. Re-executing an admitted command therefore produces different
   `created`/`updated`/`at` values. This is deliberate and matches the tools,
   and retries are safe because the receipt returns the stored outcome rather
   than re-running the effect — but it is only benign while nothing assumes
   replayability. A later step that wants deterministic replay has to thread an
   explicit clock through admission; the pure layer already takes `now` as an
   argument everywhere, so the work is in the callers, not the rules.
10. **Task id high-water seeding.** The fixed-prefix kinds keep the "high-water
   was not imported; refusing allocation" refusal. Epic-prefixed task ids have no
   counter to import for a newly created epic, so the allocator seeds the
   high-water from the live rows *and* the tombstone reservations under that
   prefix. It never recycles an id.

## Review defects found and fixed

Two confirmed defects from review, both fixed on this branch with a failing test
landed first (`d1d6f9e`, fixed in `f2dc8ca`):

- **`_bundle_members` omitted the archived filter** that legacy
  `_find_tasks_by_bundle` applies. Because a bundle pick returns before
  `PICKABLE_FROM` is consulted, it applies no status check of its own: an
  archived member was claimed back to `in-progress` while `domain.pick_task_doc`
  left its `archived` marker set, and `Transaction.replace` derives the row flag
  from that key. The result was a task both `archived=1` and `in-progress`,
  hidden from default listings, exported under `tasks/archive/` and holding a
  live session lock — the resurrection the transition table exists to prevent,
  on the one path that bypasses it. A milder second symptom: an archived
  member's `sub_repo` raised a bundle mismatch legacy would not raise. The query
  now excludes both the row flag and an `archived` status.
- **`project.set` committed an unvalidated manifest.** Admission checked only
  that the document was an object, where `backlog_project_set` calls
  `validate_manifest_dict(..., raise_on_error=True)`. A document such as
  `{"schema_version": "not-a-number", "meta": 42, "repos": "nope"}` committed
  and read back stored, which under N08 routing would write a `project.yaml`
  that `load_project_manifest` cannot parse, from a call reporting success.
  Admission now runs the same pure validator. One deliberate hardening beyond
  legacy: a malformed section reaches the validator as an `AttributeError`
  (legacy crashes on it), which is wrapped so admission always refuses with a
  value error and no database work.

## Second review pass

Four further findings, all closed:

- **The epic-archive cascade enqueued a Linear push per task** (fixed,
  `77a522c`). The tool's cascade never enqueues. Archiving a 200-task epic
  would have queued 200 pushes against a real workspace from an operation an
  operator reasonably expects to be local. The same defect was present on the
  tasks a phase advance archives, which the review had not named; both cascades
  now suppress it, while the dedicated `task.archive` still enqueues as the tool
  does.
- **`global_graph_rebuilds` was a counter nothing could increment** (removed,
  `77a522c`). Three tests asserted it read zero, which proved nothing, and this
  report cited it as evidence. The invariant it was meant to carry is now
  asserted directly: a metadata edit issues no write against `related`, `links`,
  `entity_paths` or `handover_tasks`, checked through a SQL trace callback whose
  matcher is itself verified to discriminate graph writes from ordinary reads of
  the native `declared_links` relation. The remaining counters —
  `fts_documents`, `path_comparisons`, `link_pairs`, `handover_pairs` — all
  report work actually issued.
- **`task.pick` tested the foreign lock before the status check** (fixed,
  `77a522c`). The tool tests it only inside its `in-progress` branch, so a
  `todo` or `in-review` row carrying a leftover `locked_by` is claimed rather
  than refused. The review rated this reachable only via a migrated row; it is
  in fact reachable today through `task.update locked_by`, which sets the field
  without changing status, and the regression test uses exactly that.
- **Handover smart-close losing its best-effort guard** is recorded as
  difference 8 above rather than reverted.

## Third review pass

Two more confirmed defects, both fixed (`5b4a628` tests, `87e3875` fixes):

- **The schema declared the wrong handover membership field.** `schema.KINDS`
  named `tasks`, but every handover document carries `task_ids` —
  `build_handover_doc` writes it, the handover index projects it, and legacy's
  own `handover_tasks` derivation reads it. The only occurrences of a bare
  `tasks` are epic child lists and a directory name. So
  `schema.owner("handover", "task_ids")` resolved to `entity_extensions` and the
  `memberships` table held no handover row at all. Round-trip stayed lossless —
  the list went to the extension bag and came back exactly — which is why the
  shape audit could not see it. Two live consequences: `references_to` could
  never answer "which handovers name this task", and `_smart_close_handovers`
  had to paginate every handover in the store on every `task.complete` and
  `task.archive`, because the index it should have queried was never populated.
  The declaration, the inventory's mirror of it, and the backfill's target-kind
  map are corrected; smart-close now selects only the handovers naming the task,
  and returns immediately when there are none. A regression test asserts the
  paginated listing's ordering clause never appears in a completion's SQL.
  **This changed the frozen N02 inventory** by exactly one line —
  `handover.tasks: memberships` became `handover.task_ids: memberships` — which
  is the ownership map being corrected to the field that exists, not a new
  contract. The N03 migration fixture planted `tasks` on its handover, modelled
  on the same mistake, and is corrected with it.
- **A malformed `bundle` raised a raw driver error.** `_bundle_members` bound
  the value straight into `json_extract(...)=?`, so a list- or dict-valued
  bundle — which the legacy format permits, and which this repository's own N03
  fixture plants as `[]` — produced `Error binding parameter 1: type 'list' is
  not supported` from `task.pick`, naming no task and leaving it unpickable
  until someone hand-edited the store. The tool compares in Python and proceeds.
  The dispatch now type-guards and refuses with a domain error naming the task
  and the shape, with a second guard in the helper itself.

**Staging schema version 3.** Relocating handover membership is a data-placement
change, not a DDL one, so it takes effect only on re-backfill. Version 3 makes a
version-2 staging database refuse admission until that happens, rather than
leaving it silently wrong; `upgrade_staging` accepts 1 and 2, and the caller's
re-backfill rewrites every relation. This is cheap now because staging is gated
and only tests set the authority markers — it would not be after N08.

## Where this does not reach

Native activation stays gated. No `Store` startup path invokes this core, there
is no operator activation command, and only tests set the native authority
markers. The legacy tools still write through the legacy path: N08 is what routes
them here, and until it does, "the existing completion/gate/claim, handover,
batch, auto-link and Linear test suites pass" means those suites still pass
unchanged *and* the same contracts are now separately proven against the native
core — not that their calls travel through it.
