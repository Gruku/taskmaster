# N12 implementation checkpoint: integrated; full-suite acceptance pending

The approved [scope](../plans/2026-09-22-n12-scope.md) is integrated in
`.worktrees/native-n12` on `feat/native-n12`, based on N10's `fde1648` checkpoint.
N10's final twenty copied-browser runs finished before N12 verification started;
its final evidence commit `d8d04ba` is carried here as `10ae856`. The old prepared
N12 copies in `.worktrees/native-n10` are stale; this worktree is authoritative.
All verification is serialized: one suite or benchmark at a time, hidden owned
Windows children. Native adapters now use the coordinator. The new N12 tests
were added after N10 collection and are not part of that earlier run's evidence.

Implemented, with focused integration evidence below:

- `coordinator/ownership.py`: kernel-held ownership; private discovery directory and
  atomic record publication; owner-only Windows DACL/POSIX modes; read-only
  permission verification before client trust; no PID signaling.
- `coordinator/protocol.py`: bounded JSON and coherent read-only identity.
- `coordinator/service.py`: authenticated loopback IPC, bounded admission queue,
  explicit pre-admission cancellation, durable core receipts, background N11
  export and explicit compatibility visibility barrier.
- `coordinator/client.py`: validated forwarding, exact-ID retries, private discovery,
  windowless Windows startup, no independent writer fallback.
- `coordinator/adapter.py`: read-only per-call snapshots, lazy client
  construction (reads never start a service), coordinator-only writes and
  explicit compatibility visibility. The production routing seam now delegates
  here, with structured 503/possible-commit/request-ID errors at the viewer and
  public tool boundaries. There is no direct command fallback.
- Ownership, IPC and process tests cover shared generation, duplicate retry,
  blocked export, queued/admitted cancellation, authentication/nonce refusal,
  writer recovery, explicit visibility, startup races and an owned-child crash.

First isolated check (`n12-ownership-first.out.log`): 11 passed / 1 skipped in
9.01 seconds. This includes the unchanged native-core architecture guard and
10 new ownership/IPC cases; the skipped case asserts POSIX modes on Windows.
The later first integrated batch (`n12-integrated-first.out.log`) completed with
**235 passed / 2 failed / 1 skipped in 330.97 seconds**. All three owned-process
start/crash/recovery tests, all Linear worker tests, public contracts, bypass
gates, ownership and root-probe cases passed. This is not N12 acceptance yet.

The two failures exposed different causes:

- The waiting-barrier fixture changed `meta.creation_token`, whose existing
  retained-table trigger marks staging stale. It therefore tested an unready
  authority while expecting a valid replacement-store error. The corrected test
  covers both ready replacement and stale-authority retirement explicitly.
- A real barrier bug: once background export changed a job to `conflict`, a later
  drain saw neither pending work nor a new warning and could falsely answer
  `exported`. Flush now includes durable flagged/quarantined paths. The regression
  establishes the conflict and requires three later barriers to remain pending
  and name the affected file. Focused corrections passed as recorded below.

The correction batch (`n12-service-corrections.out.log`) passed **38 tests in
61.19 seconds**, including public resolution and both replacement-authority cases.
The next independent pass found an additional cumulative barrier defect: the
N11 paragraph helper answers only for an exact commit, so a later flush could
hide an older completion, seed row, old pending list or unrun seed. All four
false-`exported` cases reproduced (`n12-progress-barrier-red2.out.log`, 9.58 s).
The new barrier-only `owes_through` preserves the old exact-commit helper and
includes every earlier owed paragraph. Later-only debt and the 12-digit key
width boundary have separate tests.

That fix's combined run passed **53 tests / failed 4 in 110.22 seconds**. All
eight new barrier cases and the actual coordinator process/root cases passed;
the four failures were old crash helpers importing `tests` from a disposable
working directory, without this worktree on the child Python path. Every
affected projection/progress crash helper now explicitly imports this checkout,
including the test-only synchronous oracle. Their crash/lease assertions are
unchanged. The complete affected group then passed **95 tests in 188.06 seconds**
(`n12-projection-compatibility.out.log`), including all cumulative barrier cases.

Independent static review found four important boundary defects in the unwired
implementation: cancellation of an already-committed retry falsely denied a
commit; background export/barriers lacked an exact-handle store fence; a short
HTTP receipt escaped recovery as a JSON parse failure; and ASCII escaping
rejected valid near-limit UTF-8 commands. Their fixes and focused regressions
passed the integrated/correction batches. Cancellation consults durable receipts; queued work,
background export and barriers fence store identity; incomplete replies retry
the identical envelope; IPC uses UTF-8. Terminal ambiguity includes the request
ID and caller scope, including IDs minted by public adapters.

IPC handler concurrency is also bounded (64 by default) independently of the
256-entry admission queue. Overload returns a structured refusal before starting
another handler, so clients do not launch new owner contenders on overload.
Additional adapter tests require a read-only handle, no service startup for
reads, the domain writer only on the owned writer thread, no projection wait in
native mode and no fallback when the owner is unavailable.

The compatibility fixtures now explicitly select the coordinator's legacy
visibility mode. Low-level N11 crash/fault tests select a frozen test-only direct
engine oracle; this preserves their primitive assertions without treating that
oracle as production-routing evidence. Separate public-tool and viewer
tests require actual IPC, asynchronous receipts, completion retry/changelog
exactly-once behavior, conflict notices/resolution and structured unavailable
errors with recoverable request IDs. An additional owned-process crash test
kills only its own child after a committed completion and before export, then
requires the replacement owner to recover both task and PROGRESS exports.
These public-routing and process checks ran in the first integrated batch; the
conflict-notice failure above passed its correction run. Static review alone is not acceptance.

A subsequent lifecycle pass found a stop/admission ordering gap: shutdown could
become visible between the guarded stop check and queue insertion, allowing an
empty writer to exit before an accepted request arrived. All production stop
paths now share the admission guard, with a passing paused-enqueue regression.
Unsafe discovery permissions also become a structured handshake refusal rather
than leaking a raw permission exception; they never trigger owner startup.

N11's deferred Linear retry now has a native queue transaction family
and separate coordinator worker. It runs only on explicit retry, not on startup
or ordinary mutations. Fake-transport tests cover target-before-limit selection,
live claim exclusion, failed-attempt accounting, edits during a push, durable
receipt replay and tracker narrative preservation. Independent review found a
stale/NULL tracker hint could lose relinked-task pushes and receipt replay depended
on current configuration. Claim-time authoritative linkage plus relink enqueue
fixes the first; lazy replay configuration with fresh-request credential preflight
fixes the second. Idle accounting includes accepted remote jobs. These fixes are
covered by the first integrated batch. Remote exactly-once delivery is not claimed.

The public `backlog_linear` contract adds optional `request_id` and `caller_scope`
inputs for replaying a native pending retry from the same or a later session.
The target must remain identical. Initial linking remains local-only; only an
already-owed push transfers on relink. Claim binding rejects a now-non-Linear
tracker before any remote call. The contract fixture and fake-transport public
pending/replay regressions were updated with these explicit additive changes.
