## Corrections to the approved scope found in code

1. The DTO reads tasks, epics and phases; it reads no backlog-document field.
   Legacy bug creation rewrites the backlog document's derived indexes. Including
   that row in the scope sequence made the non-board-write 304 test fail.
   `BOARD_KINDS` therefore names exactly the three actual input kinds.
2. The existing `assignEpicColors` honors an authored `color` field. Preserve
   that optional epic field in both language field lists; dropping it changes
   existing board colors.
3. An epic entering the board can reveal unchanged orphan tasks. Epic changes
   currently request a full resync (`epic_changed`; deletion `epic_removed`) so
   an unchanged task sequence cannot leave a client permanently incomplete.
4. The compatibility endpoint's representation depends on VERSION and SESSION_ID
   through its metadata and derived context. Its `c1` ETag includes both as well
   as the store-wide sequence. The compact board remains independent of session.
5. Historical flat layouts are an exception to item 1: their authored task index
   lives in the backlog row. Include it in the revision and use `legacy_flat`
   full resyncs. Detail reads merge the index with stored sidecars from the same
   snapshot, retaining the existing flat-layout HTTP tests.
6. Native command admission caps a batch at 100 commands. The browser cap test
   accumulates 201 changed rows across three admitted commits while holding its
   cursor, rather than inventing a supported 201-command request. A separate
   native test proves a two-task atomic commit is invisible before commit.

## Additional regressions discovered and fixed

- Independent code/spec review found two important edit races. Both reproduced
  on legacy and native: a suppressed detail refresh advanced the write ETag,
  and modal navigation cleared the DOM before locating editor disposers. Detail
  ETags now advance only on mounting the displayed revision; modal disposal
  runs before clearing. Static re-review found no remaining concern. The new
  browser regressions and complete 46-case matrix passed. The disposal test
  dispatches navigation without blur, because blur intentionally commits; it
  must isolate cancellation of a still-pending debounce.
- An Enter commit during a pending autosave could drop the newest draft. The
  failing unit regression now passes with serialized saves that drain the draft.
- A newer draft typed during a rejected save was also lost by "Keep mine".
  Its regression failed before the fix; the resolver now drains the current
  draft, suspends autosave until a conflict choice, and disposes stale banners.
- Shared optional GET helpers retain their historical fallback on 409/422,
  proven by a regression that failed before the common HTTP helper correction.
- A real copied task's scalar `blockers` made the detail rail throw
  `blockers.map is not a function`. A failing regression pins the now-supported
  scalar representation; the copy's modal smoke run then completed.
- The router cannot dispose an async detail mount before its first fetch
  returns. The screen now returns its disposer synchronously. The deterministic
  late-response regression failed on both stores before this fix and passes on
  both afterward. The first serialized suite reached 41/42; the remaining legacy
  deletion fixture incorrectly omitted a task from the compatibility dict
  instead of calling the explicit tombstone operation. That fixture is corrected
  and the final suite rerun passed all 42 cases.

## Windows liveness defect found during execution

Three test launches coincided with silent Codex CLI exits. Investigation found
`store._local_pid_alive` calling `os.kill(pid, 0)` on Windows. Python documents
that values other than CTRL_C_EVENT and CTRL_BREAK_EVENT call TerminateProcess;
zero therefore terminates a process with exit code zero. This is a concrete
destructive-probe defect, but there is no trace proving which PID caused the CLI
exits.

`bf4a9b9` pins the failure with `os.kill` replaced by a harmless assertion.
`3b4f0e8` replaces the Windows path with OpenProcess(SYNCHRONIZE) and a zero-time
WaitForSingleObject. Access failures are conservatively treated as live;
invalid PIDs are rejected. Seven tests pass, including an owned child remaining
alive through inspection and then being detected after an orderly EOF exit.
Long verification uses bounded log reads. After the user reported transient
console windows, verification is serialized to one run at a time, and the
launcher uses `CREATE_NO_WINDOW` instead of `DETACHED_PROCESS`. Do not interpret
the system-wide console-host count as this task's process count. No unrelated
processes were terminated.

Reference: https://docs.python.org/3/library/os.html#os.kill
