# N12 execution scope: one repository coordinator

The user authorized all remaining native milestones. This narrows N12's existing
design, not activation or publication. N10 remains under acceptance verification;
N12 depends on the already-merged N11 outbox. This repository has no project
backlog: the plan ledger and reports are the continuity record.

## Contract

The implementation lives in `taskmaster/coordinator/`, outside the native core.
The existing architecture gate forbids HTTP clients in `native/`; retain that
boundary instead of weakening it for local IPC. This refines the original plan's
suggested `native/service.py` placement without changing coordinator behavior.

- One kernel-held repository lock owns a coordinator generation. Discovery PID
  is diagnostic only: never signal a PID, infer ownership from it, or delete a
  lock file to take ownership. Process exit releases the kernel lock.
- Discovery is in a private local directory. Authenticated loopback IPC carries
  bounded JSON, never pickle. Tokens are restricted to the current OS user;
  Windows uses a protected DACL, POSIX owner-only modes. No remote bind.
- Every request checks canonical project root, store identity, native schema,
  command protocol and generation nonce. Stale discovery and mismatches fail
  closed. An unavailable owner never enables a direct writer fallback.
- Thin clients validate envelopes before forwarding. Retries retain the exact
  request ID and payload; committed receipts resolve disconnect ambiguity.
- A bounded admission queue feeds one domain writer. Explicit cancellation can
  remove queued work. Once admitted, the response must say the outcome may have
  committed; disconnect is not a rollback signal.
- A separate exporter, owned by that same service, uses N11's immutable jobs,
  expected-base checks and leases. Normal native commands return after durable
  commit with a projection receipt, without rendering or scanning files.
- Compatibility visibility is an explicit mode over the same coordinator: wait
  for export through the commit, then report exported or pending/conflicted.
  It is not permission to open a second legacy writer. True legacy-authority
  projects keep their existing implementation until migration is authorized.
- Native read adapters open read-only committed snapshots. Service startup,
  reconnect and idle shutdown must not create visible Windows console windows.
- N11's deferred Linear retry uses a separate, bounded coordinator worker. Only
  an explicit retry requests remote work; startup and ordinary edits do not.
  Claims and settlement use the sole native writer; no remote I/O holds its
  transaction or a publication lock. Exact retry keys recover local receipts.
  Remote acknowledgement lost before settlement remains honestly at-least-once.
  The response may report pending after 20 seconds; the same key inspects that
  finite batch, while a new retry key explicitly grants a new attempt budget.

## Build and evidence sequence

1. Private discovery, ownership lock, handshake and lifecycle tests.
2. Queue, cancellation, exact retry receipts and disconnect tests.
3. Background export, restart recovery and explicit visibility barrier.
4. Route native mutation adapters through the client; retain direct engine calls
   only in explicit core tests. No silent production fallback.
5. Process tests for concurrent start, stale PID/nonce, unsupported protocol,
   owner crash/restart, cleanup and multiple clients sharing one generation.
6. Full regression and deterministic counters proving no projection work on the
   normal command thread. Record failures and scope limits before updating N12.

N13 adds external import, finite generation barriers and managed Git pinning;
N12 must provide coordination seams but must not claim those features early.
N15 rehearses migration on copies. N17 selects and validates a release candidate.
No installation, live CodeMaestro activation, push or publication is authorized.
